# 卡车助手 AI 问答 — 云端需求清单

> **版本**: W52 | **日期**: 2026-09-03 | **状态**: Draft

---

## 1. 概述

卡车助手是 APP 内嵌的 AI 问答功能，用户通过自然语言提问，基于官方车书知识库获取即时答案。云端负责 RAG 检索、答案生成、会话管理、内容配置和数据处理。

**一期范围**: 仅车书相关问题，一款在售车型，中文。

---

## 2. 语义识别

### 2.1 意图分类

云端需对用户问题做语义理解，识别以下意图类型，触发不同的回复策略。分类对应 PRD 的 9 种场景：

| 意图 | 对应 PRD 场景 | 描述 | 触发词示例 | 处理策略 |
|------|:---:|------|-----------|---------|
| 车书查询 | 正常问答 | 车辆功能操作、使用方法 | "方向盘怎么调"、"换挡步骤" | 正常 RAG 检索 + 生成 |
| 报警灯 | 正常问答 | 仪表盘报警灯含义 | "这个灯亮了"、"黄色感叹号" | 优先检索报警灯知识库 |
| 保养咨询 | 正常问答 | 保养周期、项目 | "首保什么时候"、"机油型号" | 正常 RAG 检索 + 生成 |
| 参数配置 | 正常问答 | 车辆规格、参数 | "续航多少"、"电池容量" | 正常 RAG 检索 + 生成 |
| 购车咨询 | 正常问答 | 车型对比、配置选择 | "E27和E29区别" | 正常 RAG 检索 + 生成 |
| 内容安全 | 内容安全 | 政治/暴力/色情/辱骂/违规 | — | 拒识，不展示建议追问 |
| 紧急安全 | 紧急安全 | 刹车失灵、起火等 | "刹车失灵"、"冒烟了" | 紧急处理建议 + 400 |
| 投诉抱怨 | 投诉抱怨 | 产品质量投诉 | "质量太差"、"我要投诉" | 共情 + 400 |
| 竞品比较 | 竞品比较 | 与其他品牌对比 | "沃尔沃和你们谁好" | 拒识，引导到 Scania |
| 模糊问题 | 模糊问题 | 意图不明确 | "坏了怎么办"、"不好使" | 引导追问 |
| 超出知识库 | 超出知识库 | 价格/金融/闲聊等 | "多少钱"、"你好" | 拒识 + FAQ + 400 |
| 重复问题 | 重复问题 | 短时间重复提问 | 同一问题反复问 | 引导换角度 + 400 |
| 服务异常 | 服务异常 | 系统异常、请求超时 | — | 提示稍后重试 |

### 2.2 多轮意图消歧

- 同一 Session 内，需结合上下文消歧用户意图
- 示例："方向盘怎么调" → "那调多高合适" → 后端需理解"那"指代"方向盘"
- 消歧范围：最近 10 轮对话

### 2.3 实体识别

| 实体类型 | 说明 | 示例 |
|---------|------|------|
| 车辆部件 | 方向盘、后视镜、座椅、空调等 | "方向盘怎么调" → 部件=方向盘 |
| 操作动作 | 调节、打开、关闭、更换等 | "怎么调" → 动作=调节 |
| 报警灯 | 具体报警灯类型 | "黄色感叹号" → 报警灯=胎压警告 |
| 车型 | 车型名称 | "E27 续航多少" → 车型=E27 |

## 3. 回复风格

### 3.1 人格设定

| 维度 | 设定 |
|------|------|
| 角色 | Scania 卡车助手，专业、可靠、友善 |
| 语气 | 简洁直接，不啰嗦，口语化但不随意 |
| 人称 | 使用"你"称呼用户，自称"我" |
| 语言 | 仅中文，不使用英文术语（除非是产品名称如 NEXT ERA） |

### 3.2 回复结构规范

**正常答案**:
```
1. 直接回答核心问题（1-2 句）
2. 分步操作说明（如有操作步骤，使用编号列表）
3. 补充提示/安全提醒（如有）
4. 车书章节链接（如有）
```

**示例**:
```
方向盘调节步骤如下：

1. 找到方向盘下方的调节杆
2. 向下推动调节杆解锁
3. 调整方向盘到合适的高度和角度
4. 向上拉回调节杆锁定位置

推荐：方向盘上沿与肩膀齐平，手臂自然弯曲约120度。

安全提示：请勿在行驶中调节方向盘。
```

**拒识回复**:
```
1. 简短道歉/说明（1 句）
2. 原因说明（1 句）
3. 引导建议（建议追问或 400 电话）
```

### 3.3 禁止行为

| 禁止 | 说明 |
|------|------|
| 编造信息 | 知识库没有的内容不得凭空生成 |
| 评价竞品 | 不与其他品牌做优劣对比 |
| 给出承诺 | 不对价格、交付时间等做承诺 |
| 医疗/法律建议 | 不提供超出车书范围的专业建议 |
| 生成图片 | 不生成新图片，仅引用已有素材 |
| 英文回复 | 一期仅支持中文 |

### 3.4 边界场景回复文案

| 场景 | 回复模板 |
|------|---------|
| 敏感/违规 | 抱歉，这个问题我暂时无法回答。您可以换个方式问我，我很乐意为您提供帮助。 |
| 法规合规 | 这个问题涉及法规合规，建议您咨询官方渠道获取准确信息。我很乐意帮您解答其他车辆使用方面的问题。 |
| 人身攻击 | 抱歉给您带来了不好的体验。如果您有任何车辆使用方面的问题，我很乐意为您解答。 |
| 紧急安全 | 请立即靠边停车，确保安全。以下为紧急处理建议：\n\n1. 开启双闪警示灯\n2. 在车后方放置三角警示牌\n3. 人员撤离至安全区域\n4. 拨打客服热线 400-xxx-xxxx 获取进一步指导 |
| 投诉抱怨 | 非常抱歉给您带来了不好的体验，我理解您的感受。建议您拨打客服热线 400-xxx-xxxx，我们将尽快为您处理。 |
| 竞品比较 | 每个品牌都有自己的优势，我无法对竞品做出评价。不过如果您想了解 Scania 车型的特点，我很乐意为您详细介绍！ |
| 模糊问题 | 能具体描述一下是什么问题吗？比如哪个功能不会用、哪个报警灯亮了？我很乐意为您提供帮助。 |
| 超出知识库 | 抱歉，当前知识库中暂时没有相关信息。关于价格和金融方案，建议您拨打客服热线 400-xxx-xxxx 咨询，我可以帮您解答其他车辆使用问题。 |
| 重复问题 | 您刚才问过同样的问题，建议您换一种方式提问，或拨打客服热线 400-xxx-xxxx 获取帮助。 |
| 普通拒识 | 抱歉，当前知识库中没有找到与您的问题相关的信息。建议您换一种方式提问，我很乐意为您提供帮助。 |
| 闲聊 | 你好！我是卡车助手，可以帮你解答车辆使用方面的问题。比如"方向盘怎么调"、"仪表盘报警灯亮了怎么办"。 |

### 3.5 格式化输出

- 操作步骤：使用编号列表（1. 2. 3.）
- 安全提示：加粗 **安全提示：**
- 重要信息：加粗
- 段落间：空一行
- 答案末尾：固定展示免责声明

## 4. 车书 Agent API

### 2.1 问答接口

**接口描述**: 用户发送问题，云端基于车书知识库进行 RAG 检索并生成答案，以 SSE 流式返回。

**请求**:
```
POST /api/v1/chat/ask
Content-Type: application/json
Authorization: Bearer {token}

{
  "session_id": "uuid",           // 会话 ID，用于多轮对话上下文
  "question": "方向盘怎么调？",     // 用户问题（最长 500 字）
  "vin": "LSV****1234",           // 车辆 VIN（脱敏后），用于匹配知识库车型
  "timestamp": 1693728000
}
```

**响应（SSE 流式）**:
```
event: thinking
data: {"status": "searching", "message": "正在查找车书..."}

event: thinking
data: {"status": "organizing", "message": "正在组织答案..."}

event: token
data: {"content": "方向盘"}

event: token
data: {"content": "调节"}

...

event: done
data: {
  "content": "完整答案文本...",
  "images": [
    {"url": "https://cdn.xxx.com/images/steering.jpg", "alt": "方向盘调节示意图"}
  ],
  "links": [
    {"text": "车书第3.2.1章节", "url": "app://manual/3.2.1"}
  ],
  "rejected": false,
  "disclaimer": "内容由AI生成，仅供参考"
}
```

**响应字段说明**:

| 字段 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| content | string | ✅ | 答案文本（Markdown 格式） |
| images | array | ❌ | 域内已有图片素材，仅返回 URL，不生成新图 |
| images[].url | string | ✅ | 图片 CDN 地址（HTTPS） |
| images[].alt | string | ✅ | 图片描述 |
| links | array | ❌ | 车书章节跳转链接 |
| links[].text | string | ✅ | 链接展示文案 |
| links[].url | string | ✅ | APP 内车书模块 deeplink |
| rejected | boolean | ✅ | 是否拒识 |
| disclaimer | string | ✅ | 免责声明文案 |

**性能要求**:
- 首 Token 响应时间（TTFT） < 3 秒
- 流式输出速率 ≥ 30 tokens/秒

### 2.2 拒识返回

当知识库无匹配或触发边界场景时，`rejected: true`：

```json
{
  "rejected": true,
  "reject_type": "out_of_knowledge",
  "content": "抱歉，当前知识库中暂时没有相关信息...",
  "suggestions": [
    "如何查看车辆续航里程？",
    "仪表盘报警灯亮了怎么办？"
  ],
  "escalation": {
    "text": "拨打我们的客服热线，人工客服将为您解答。",
    "phone": "400-xxx-xxxx"
  },
  "disclaimer": "内容由AI生成，仅供参考"
}
```

**拒识类型（reject_type）**:

| 类型 | 对应 PRD 场景 | 说明 | 建议追问 | 展示FAQ | 客服入口 |
|------|-------------|------|:---:|:---:|:---:|
| safety | 内容安全 | 敏感/违规/法规合规/人身攻击 | ✅ | ❌ | ❌ |
| emergency | 紧急安全 | 紧急安全问题 | ✅ | ❌ | ✅ |
| complaint | 投诉抱怨 | 投诉抱怨 | ✅ | ❌ | ✅ |
| competitor | 竞品比较 | 竞品对比、评价 | ✅ | ❌ | ❌ |
| vague | 模糊问题 | 问题信息不充分 | ✅ | ❌ | ❌ |
| out_of_knowledge | 超出知识库 | 知识库无匹配 | ✅ | ✅ | ✅ |
| repeated | 重复问题 | 短时间重复提问 | ✅ | ❌ | ✅ |
| service_error | 服务异常 | 系统异常、请求超时 | ✅ | ❌ | ❌ |

### 2.3 多轮对话上下文

**Session 管理**:
- 同一 `session_id` 内的请求，云端需维护对话历史（最近 10 轮）
- 后续请求需基于历史上下文生成答案（如理解"那"、"它"等指代）
- Session 超时：5 分钟无新请求 → 自动失效，下次请求创建新 Session

**新对话**:
- 客户端生成新 `session_id` → 云端创建新 Session
- 旧 Session 数据保留，用于历史消息加载

### 2.4 历史消息查询

**接口描述**: 客户端上拉加载时，分页获取历史消息。

**请求**:
```
GET /api/v1/chat/history?session_id={uuid}&before={timestamp}&limit=20
Authorization: Bearer {token}
```

**响应**:
```json
{
  "messages": [
    {
      "role": "user",
      "content": "方向盘怎么调？",
      "timestamp": 1693728000
    },
    {
      "role": "assistant",
      "content": "方向盘调节步骤如下：...",
      "images": [...],
      "links": [...],
      "timestamp": 1693728010
    }
  ],
  "has_more": true
}
```

### 2.5 反馈上报

**接口描述**: 用户点赞/不点赞后，上报反馈数据。

**请求**:
```
POST /api/v1/chat/feedback
Content-Type: application/json
Authorization: Bearer {token}

{
  "session_id": "uuid",
  "message_id": "uuid",
  "feedback": "like" | "dislike",
  "timestamp": 1693728000
}
```

## 5. 认证与安全

### 3.1 Token 认证

- 所有 API 请求携带 `Authorization: Bearer {token}`
- Token 过期时，云端返回 401 → 客户端使用 refresh token 刷新
- 刷新过程对用户透明，不中断体验

### 3.2 数据脱敏

- 埋点日志不包含完整 VIN（仅保留前 3 位 + 后 4 位）
- 日志不包含用户真实姓名、手机号
- API 请求日志中 VIN 同样脱敏

### 3.3 限流

- 单用户：每秒最多 1 次请求
- 超出返回 429 + 提示文案

## 9. RAG 管线

### 9.1 文档切分

| 维度 | 建议 |
|------|------|
| 切分策略 | 按章节 + 小节层级切分，保持语义完整性 |
| Chunk Size | 500-800 tokens，按段落边界截断，避免句子被切断 |
| Overlap | 相邻 chunk 重叠 50-100 tokens，防止关键信息落在边界 |
| 元数据 | 每个 chunk 附带：章节编号、章节标题、页码 |

### 9.2 向量化

| 维度 | 建议 |
|------|------|
| 模型 | 中文 Embedding 模型（如 text2vec-large-chinese 或 bge-large-zh） |
| 维度 | 768 或 1024 |
| 索引 | 向量数据库（Milvus / Pinecone / Weaviate） |

### 9.3 检索策略

| 维度 | 建议 |
|------|------|
| 检索方式 | 混合检索：语义检索 + BM25 关键词检索，取并集 |
| Top-K | 初步检索 top-20，经重排序后取 top-5 送入 LLM |
| 重排序 | 使用 Cross-Encoder 模型重排序（如 bge-reranker-large） |
| 过滤 | 按车型过滤（基于 VIN 匹配车型），仅检索对应车型的文档 |

### 9.4 上下文窗口管理

- 拼接 top-5 文档片段，总长度不超过 4000 tokens
- 超出部分按重排序得分截断，低分片段丢弃
- 拼接时按章节顺序排列，保持逻辑连贯

## 10. Prompt 工程

### 10.1 System Prompt

```
你是 Scania 卡车助手，一个专业、可靠、友善的 AI 助手。
你的知识来源于官方车书，回答必须基于提供的参考文档。

回复规则：
1. 直接回答核心问题，不啰嗦
2. 操作步骤使用编号列表（1. 2. 3.）
3. 安全提示加粗
4. 段落间空一行
5. 不使用英文术语（产品名称除外）
6. 不确定的内容不要说，不要编造
7. 不评价竞品，不做价格承诺
```

### 10.2 意图 Prompt 模板

**正常问答**:
```
参考文档：
{context}

用户问题：{question}
对话历史：{history}

请基于参考文档回答用户问题。如果参考文档中没有相关信息，请标记为拒识。
```

**拒识场景**:
```
注意：以下问题超出车书知识库范围，请用友善语气告诉用户你无法回答，
并给出 2-3 个相关建议追问。不要编造答案。
```

**紧急安全场景**:
```
这是紧急安全问题。请先给出紧急处理步骤，再引导用户拨打客服热线。
格式：先贴安全步骤，再贴客服入口。
```

### 10.3 Few-shot 示例

- 正常问答：2-3 个车书问答示例
- 拒识：2-3 个拒识回复示例
- 建议：嵌入 System Prompt 或检索相关示例动态注入

## 11. 幻觉防控

### 11.1 Grounding 校验

- 答案中每个事实性断言需能追溯到参考文档中的具体片段
- 生成后提取关键事实，与 top-5 文档做语义相似度校验
- 相似度 < 阈值（如 0.7）的断言标记为"可能不准确"

### 11.2 引用验证

- 答案中引用的车书章节编号（如"第 3.2.1 章节"）需验证真实存在
- 图片 URL 需验证在 CDN 中可访问
- 验证失败时，不展示链接或图片

### 11.3 兜底策略

- 当检索结果相关性过低（top-1 得分 < 阈值）时，不强行生成答案
- 直接返回拒识 + 建议追问，避免"一本正经胡说八道"

## 12. 内容安全（双层护栏）

### 12.1 输入护栏（Pre-Guard）

**检测时机**: 用户问题进入 RAG 之前

| 检测项 | 方法 | 处理 |
|--------|------|------|
| 敏感词 | 敏感词库匹配 | 拦截，返回拒识 |
| 合规风险 | 关键词 + 语义分类 | 拦截，返回拒识 |
| 注入攻击 | Prompt Injection 检测 | 拦截，返回拒识 |
| 超长输入 | 长度限制 500 字 | 截断，返回提示 |

**处理流程**:
```
用户输入 → 输入护栏检测 → 通过 → RAG 检索 → LLM 生成 → 输出护栏检测 → 返回
                           → 拦截 → 返回拒识文案
```

### 12.2 输出护栏（Post-Guard）

**检测时机**: LLM 生成之后、返回客户端之前

| 检测项 | 方法 | 处理 |
|--------|------|------|
| 敏感词 | 生成文本敏感词扫描 | 替换为拒识文案 |
| 竞品提及 | 品牌名检测 | 替换为拒识文案 |
| 价格/承诺 | 正则 + 语义检测 | 删除相关语句 |
| 幻觉断言 | 事实一致性校验 | 删除不可验证的断言 |

## 13. 缓存策略

### 13.1 语义缓存

- 对用户问题做语义指纹（向量化后取 hash）
- 新问题与缓存中问题的语义相似度 > 0.95 → 直接返回缓存答案
- 缓存有效期：车书更新时整体失效

### 13.2 缓存分层

| 层级 | 策略 | TTL |
|------|------|-----|
| L1 热点缓存 | 高频问题（日访问 > 100 次） | 24h |
| L2 常规缓存 | 相似度 > 0.95 的问题 | 1h |
| L3 拒识缓存 | 已拒识的问题（避免重复处理） | 1h |

### 13.3 预期效果

- 高频问题（如"方向盘怎么调"）命中缓存后 TTFT < 100ms
- 预计缓存命中率 30-40%，节省 LLM 调用成本

## 附录：AI 专业术语解读

> 以下用通俗语言解释文档中涉及的核心 AI 概念，方便非 AI 背景的团队成员理解。

### A.1 RAG（检索增强生成）

**通俗理解**："先翻书再回答"。

AI 不会把整本车书记在脑子里。每次收到用户问题后，先去知识库里翻出相关段落，再把这些段落作为参考材料喂给 LLM，让 LLM 基于这些材料生成答案。这样做的好处是答案有据可查，不会凭空编造。

**类比**：你是客服，客户问"方向盘怎么调"，你不会凭记忆随便说，而是先翻开车书相关章节，照着书上的内容回答。

### A.2 文档切分（Chunking）

**通俗理解**：把一本厚书拆成小卡片。

一本车书几万字，一次全塞给 LLM 会超出它的处理能力（窗口限制）。所以要切成小块，每块 500-800 字。块与块之间重叠 50-100 字，防止关键信息刚好在切分边界被切断。

**类比**：把一本 300 页的说明书裁成 500 张卡片，每张卡片上写一个知识点。有人问"方向盘怎么调"，你只需要找到那几张相关的卡片，不用翻整本书。

### A.3 向量化（Embedding）

**通俗理解**：把文字转成数学坐标。

每个词、每句话都被转成一组数字（比如 1024 个数字），代表它在语义空间中的位置。语义相近的句子，坐标也相近。"方向盘怎么调"和"如何调整方向盘"坐标会很接近，但和"今天天气真好"坐标很远。

**类比**：把每个问题放在一张大地图上，相似的问题聚在一起。用户问"方向盘怎么调"，你直接去地图上"方向盘"附近找，就能找到所有相关答案，不用全图搜索。

### A.4 混合检索（Hybrid Search）

**通俗理解**：语义匹配 + 关键词匹配，两种方式取长补短。

语义检索能理解"调"和"调整"是同义词，但可能漏掉专有名词。关键词检索能精确匹配"NEXT ERA E27"，但不理解近义词。两种结果合并，覆盖率更高。

**类比**：语义检索是"找意思相近的"，关键词检索是"找字面相同的"。两者结合，既不漏掉相关的内容，也不漏掉精确匹配的术语。

### A.5 重排序（Reranking）

**通俗理解**：初筛 20 条，精选 5 条。

初步检索可能返回 20 条相关文档，但其中有些只是"沾边"。重排序模型会逐条打分，把最相关的 top-5 挑出来送入 LLM。这步是"精排"，确保 LLM 看到的都是高质量参考材料。

**类比**：HR 初筛 20 份简历，交给用人经理精挑 5 份进入面试。精挑比初筛更精准，但成本更高，所以只对初筛结果做。

### A.6 Prompt 工程

**通俗理解**：给 AI 的指令说明书。

Prompt 就是你告诉 AI "你是谁、怎么说话、不能做什么"的指令。好的 Prompt 让 AI 回答专业、准确、风格统一；差的 Prompt 让 AI 回答混乱、跑题、甚至胡编。

System Prompt 是每次对话开头固定不变的"人设设定"，比如"你是 Scania 卡车助手，专业可靠，不评价竞品"。Few-shot 是在 Prompt 里放 2-3 个标准答案示例，让 AI 模仿格式和语气。

**类比**：给新员工写岗位说明书 + 给他看几个优秀案例。岗位说明书告诉他要做什么，案例告诉他怎么做才算好。

### A.7 幻觉（Hallucination）

**通俗理解**：AI 一本正经地胡说八道。

LLM 有时候会编造看起来很合理、但实际不存在的内容。比如用户问"车书第 3.2.1 章节"，AI 可能编一个不存在的章节编号。幻觉是 LLM 的固有问题，无法完全消除，只能通过校验和兜底策略来防控。

**Grounding 校验**就是检查答案中每个事实说法是否能在车书原文中找到依据。找不到的标记为"可能不准确"或直接删除。

**类比**：一个实习生为了表现自己，被问到不会的问题时，不是老实说"不知道"，而是编一个听起来很专业的答案。你需要有个老员工审核他的回答，确保每个说法都有出处。

### A.8 内容安全护栏（Guardrails）

**通俗理解**：AI 系统的安检门，分输入和输出两层。

**输入护栏**：用户问题在进 AI 之前先安检。检测敏感词、恶意注入（比如用户说"忽略之前的指令"）、超长输入。不合格的直接拦截，不浪费后续资源。

**输出护栏**：AI 生成答案后再安检一次。模型可能被绕过，或者意外说出不该说的内容。检测品牌名、价格承诺、幻觉断言。

**为什么两层**：输入护栏拦截明显恶意，输出护栏兜底漏网之鱼。就像机场安检，进候机楼查一次，登机口再查一次。

**类比**：公司前台先过滤掉推销电话（输入护栏），客服主管再抽查通话录音确保没有违规承诺（输出护栏）。

### A.9 语义缓存（Semantic Cache）

**通俗理解**：不是缓存"相同问题"，而是缓存"意思相同的问题"。

"方向盘怎么调"和"如何调整方向盘"字面不同但意思一样。向量化后相似度 > 0.95，直接返回之前生成好的答案，不用再走一遍 RAG + LLM 流程。

**价值**：高频问题每天被问几百次，每次都调 LLM 既慢又贵。缓存命中后，响应时间从 3 秒降到 < 100ms，成本大幅下降。

**类比**：客服把常见问题的标准答案贴在工位旁边。客户问"方向盘怎么调"和"方向盘在哪里调"，你一看就知道是同一个问题，直接贴答案，不用再翻书。

### A.10 建议追问生成

**通俗理解**：AI 答不上来时，给用户 2-3 个可能想知道的替代问题。

不是让用户碰壁就放弃，而是给个台阶"你试试问这个"。一期用语义检索方式：预先建一个"问题库"，把 FAQ 和高频问题全部向量化。拒识时，用用户问题的向量在问题库里找最相似的 3 个，返回给用户。

**类比**：客户问"你们打折吗"，你说"不好意思我们不涉及价格，但你可以问我'这车续航多少'、'有什么配置'、'保养周期是多久'"。

### A.11 LLM-as-Judge

**通俗理解**：用另一个 AI 给 AI 打分。

人工评估 100 条答案太慢太贵，所以用另一个 LLM 来评判答案质量，对比标准答案自动打分。不能完全替代人工，但可以把人工工作量从 100% 降到 10-20%——只复核低分答案和争议答案。

**类比**：老师布置 100 篇作文，先让助教批改出分数，老师只抽查 20 篇有争议的，不用每篇都看。

### A.12 容灾与降级

**通俗理解**：主方案挂了怎么办，要有备选方案。

不是"AI 挂了就挂了"，而是层层降级：
1. 主模型超时 → 切备选模型（换一个 LLM）
2. 备选也挂 → 返回预设 FAQ 答案（不依赖 AI 的静态答案）
3. 向量数据库挂 → 降级为关键词检索（不用 AI 搜索，用传统搜索）
4. 全线崩溃 → 返回错误提示 + 400 电话

每一层降级体验都会变差，但比完全不可用强。

**类比**：高速堵车走国道，国道也堵走省道，省道也堵至少给你个导航告诉你"实在不行打这个电话问路"。每一级都比上一级慢，但最终不会让你困在原地。

### A.13 首 Token 响应时间（TTFT）

**通俗理解**：从用户点发送，到屏幕上出现第一个字的时间。

这是用户感知最强烈的指标。TTFT < 3 秒，用户觉得"还行"；TTFT > 5 秒，用户觉得"是不是卡了"；TTFT > 10 秒，用户可能直接退出。

**类比**：你去餐厅点菜，服务员说"好的"然后去厨房，这 3 秒内你觉得一切正常。如果 10 秒没人理你，你开始怀疑是不是被忘了。
